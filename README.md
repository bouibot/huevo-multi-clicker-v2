# huevo multi-clicker v2 (Telegram-бот)

Мульти-кликер копилки [huevo.su](https://huevo.su) как «услуга»: клиенты заходят в
Telegram-бота, добавляют свой логин/пароль, решают капчу в чате - ферма на твоём VPS
фармит копилку этого аккаунта. Когда аккаунт за день накликает первые **10 000 монеток**,
бот сам переводит их через `POST /coins/send` на аккаунт владельца (комиссия).

Ядро взято из референсного автокликера (`../huevoclicker`): антибот 418 (XOR-Advance `hchk`),
логин с капчей (`data-k` → `hv`), POST `/api/clicker` (batch ≤ 400, MIN_GAP 8 с),
дневной кап «full», автосохранение/переиспользование cookies.

## Что нового в v2

- 📢 **`/broadcast`** - рассылка любому тексту (поддерживает HTML) всем юзерам бота
  с предпросмотром и подтверждением; уведомления юзеров копятся в таблице `users`.
- 🔔 В `/start` добавлена просьба подписаться на сообщества
  ([t.me/lovemelikeimdead](https://t.me/lovemelikeimdead), [huevo.su/autofarm](https://huevo.su/autofarm))
  с кнопками-ссылками.
- 👥 **Мульти-админка**: владелец задаётся в `.env` (`OWNER_ID`) и один может
  добавлять/удалять админов по Telegram ID: команды `/adminadd <id>`, `/admindel <id>`,
  список - `/admins`. Все админы имеют доступ к `/admin` и получают уведомления
  (комиссии, ошибки перевода и т.п.).
- 🐛 Фикс: в `engine.mjs` не был импортирован `CAPTCHA_WAIT_MS` (падало на ветке «код не получен»).
- 🆓 Аккаунты, добавленные админами (и владельцем), не платят комиссию - весь фарм остаётся им.

## Функции

- 📥 Клиент в боте: `/add` → логин → пароль → **капча фото** → код ответным сообщением.
- 🍀 Постоянный фарм: кликаем `400 × раз в ~8.5 с`, автоперелогин при смерти сессии.
- 💸 Комиссия: как только за день накопилось ≥ порога (10 000) - перевод `последнему`
  аккаунту владельца. Один раз в день с каждого аккаунта; аккаунт-приёмник сам себя
  не переводит. Аккаунт приёма и сумма настраиваются в `/admin`.
- 🔑 Перезапуск бота: все аккаунты и сессии уже в SQLite; если при старте сессия
  мертва, бот шлёт клиенту кнопку «Перелогиниться» - по нажатию приходит капча
  (без авто-спама капчей). Всё сохраняется в `data/clicker.db`.
- 🛠 Админ (`/admin`): сменить аккаунт-приёмник комиссии, сумму, история переводов,
  список всех аккаунтов, рассылка, управление админами.
- Уведомления: успешный вход, запрос капчи, выплата комиссии, сетевые проблемы.

## Права в боте

| Кто | Что может |
|-----|-----------|
| Любой юзер | `/add`, `/accounts`, капчи, смена пароля своего аккаунта |
| Админ (из БД) | `/admin` (просмотр цифр: переводы, аккаунты, юзеры), `/broadcast`, `/admins` |
| Владелец (`.env OWNER_ID`) | всё выше + `/adminadd`, `/admindel`, смена аккаунта/суммы комиссии |

Настройки комиссии (`🏦 аккаунт приёма`, `💰 сумма`) видны и меняются
**только владельцем** - обычный админ видит их значения в тексте панели,
а кнопок изменения у него нет.

Если `OWNER_ID` не задан и в БД нет владельца - первый, кто вызовет `/admin`,
станет владельцем (claim).

## Деплой на VPS

```bash
# Node.js 22.5+ (лучше 24 LTS): https://nodejs.org
git clone <твой-репо> huevo-multi-clicker
cd huevo-multi-clicker
npm install

# конфиг: скопируй пример и заполни (BOT_TOKEN, OWNER_ID) - .env в гит не попадает
cp .env.example .env
nano .env

# старт вручную (проверка)
npm start

# автозапуск через systemd (юнит в deploy/huevo-clicker.service):
sudo tee /etc/systemd/system/huevo-clicker.service > /dev/null < deploy/huevo-clicker.service
sudo systemctl daemon-reload
sudo systemctl enable --now huevo-clicker
journalctl -u huevo-clicker -f
```

> ⚠️ `.env` (там токен бота) и пароли аккаунтов в `data/clicker.db` не публикуй в гит:
> они в `.gitignore`, проверь перед push (`git status` не должен показывать `.env`).

## Как это работает внутри

| Файл             | Что делает |
|------------------|------------|
| `src/config.mjs` | .env, константы (паузы кликов 8.4 с, капча-таймаут 10 мин, ссылки на сообщества, пауза рассылки) |
| `src/db.mjs`     | SQLite (встроенный `node:sqlite`): аккаунты, cookies, статистика, переводы, юзеры для рассылки, админы, настройки |
| `src/site.mjs`   | HTTP-клиент huevo.su: антибот 418, логин, капча `/captcha/refresh/login`, кликер, `POST /coins/send` (перевод) |
| `src/engine.mjs` | Цикл фарма на аккаунт: сессия → клик → комиссия; логины сериализуются (IP-лимит на неудачный вход) |
| `src/bot.mjs`    | grammY: диалоги, капча-очередь (FIFO на чат), меню аккаунтов, админ-панель, рассылка, мульти-админка |
| `src/index.mjs`  | Сборка всего вместе |

## Ограничения сайта (учтено)

- `MIN_GAP_SECONDS = 8000` между кликами, `MAX_BATCH = 400` за запрос.
- Дневной кап: `/api/clicker` отдает `{"capped":true,"error":"full"}` - не ошибка, ждём сброса (10 мин циклы).
- Капча обязательна только на логине; пока жива кука `session` - капча не нужна (cookies в БД).
- После нескольких неверных входов сервер лочит логин по IP (~5 мин) - логины идут строго по очереди с паузами.
- Telegram: рассылка идёт с паузой ~55 мс (~18 msg/s), ниже лимита 30 msg/s.

## Важно

- Пароли клиентов хранятся в SQLite открытым текстом (нужно для автоперелогина) - держи VPS под замком.
- Капча решается **вручную клиентом в боте**; если клиент оффлайн, аккаунт «спит» 30 мин и спрашивает снова.
- Комиссия с аккаунта списывается ровно 1 раз в день, даже если накликали 20к - излишек остаётся клиенту.
- Аккаунты админов и владельца (подключенные через их Telegram ID) комиссию **не платят**.
- Не забудь: 10000 монеток с аккаунта списываются в момент перевода; баланс клиента после этого околонулевой.
